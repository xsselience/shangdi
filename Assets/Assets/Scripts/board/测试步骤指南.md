# 棋盘系统完整测试步骤

## 📋 测试前准备

### 1️⃣ 确认Unity版本
- 打开Unity Hub
- 确认项目使用的Unity版本（建议2021.3 LTS或更高）
- 如果项目未打开，点击项目名称打开

### 2️⃣ 检查编译状态
打开Unity后，等待编译完成：
- 查看Unity窗口右下角，应该显示"✓ All scripts compiled successfully"
- 如果有编译错误，查看Console窗口（Window → General → Console）

## 🎮 方式一：使用简单测试脚本（推荐新手）

这是最简单的测试方式，无需配置UI，适合快速验证功能。

### 第1步：打开测试场景

1. **创建新场景**
   - 菜单栏 → File → New Scene
   - 选择 "Empty" 或 "2D"

2. **保存场景**
   - File → Save As
   - 命名为 "BoardTestScene"
   - 保存到 `Assets/Scenes/` 文件夹

### 第2步：创建测试对象

1. **创建空物体**
   - Hierarchy 窗口（左侧）
   - 右键 → Create Empty
   - 命名为 "BoardTest"

2. **添加测试脚本**
   - 选中 "BoardTest" 对象
   - Inspector 窗口（右侧）→ Add Component
   - 搜索 "BoardSimpleTest2D"
   - 点击添加

### 第3步：配置测试参数

在 Inspector 窗口的 BoardSimpleTest2D 组件中：

| 参数 | 推荐值 | 说明 |
|------|--------|------|
| Board Width | 10 | 棋盘宽度 |
| Board Height | 10 | 棋盘高度 |
| Initial Piece Count | 15 | 初始棋子数量（建议10-20） |
| Obstacle Count | 10 | 障碍物数量（建议5-15） |
| Step Limit | 30 | 步数限制 |

### 第4步：运行测试

1. **点击Play按钮**（Unity顶部中央）
2. **等待棋盘生成**（1-2秒）

### 第5步：功能测试

#### ✅ B1: 棋盘系统测试
**预期结果**：
- 看到 10×10 的棋盘格子
- 格子整齐排列
- 障碍物显示为深灰色方块
- 棋子显示为彩色方块：
  - 🔴 红色 = 火元素
  - 🔵 蓝色 = 水元素
  - 🟦 青色 = 风元素
  - 🟡 黄色 = 土元素

#### ✅ B2: 棋子刷新测试
**操作步骤**：
1. 点击任意棋子（格子变黄 = 选中成功）
2. 点击相邻的空格子移动
3. 观察新棋子是否在随机位置生成

**预期结果**：
- 每次移动后刷新1个新棋子
- 新棋子位置随机
- 新棋子元素随机（火水风土之一）

#### ✅ B3: 棋子移动测试
**操作步骤**：
1. 点击一个棋子
2. 尝试点击它上/下/左/右的格子
3. 尝试点击斜向格子（应该无法移动）
4. 尝试点击障碍物（应该无法移动）

**预期结果**：
- 只能移动到上下左右相邻空格
- 不能斜向移动
- 不能移动到障碍物
- 不能移动到有其他棋子的格子
- 移动后棋子立即出现在目标位置

#### ✅ B4: 五连合成测试
**操作步骤**：
1. 尝试移动相同颜色的棋子形成5连
2. 可以是横向、纵向、或斜向

**预期结果**：
- 五个相同颜色的棋子连成一线时触发合成
- 这5个普通棋子消失
- 在移动的最终位置生成1个特种棋子（亮黄色⭐圆形）
- Console显示："合成成功！生成特种棋子"

**触发合成的例子**：
```
横向五连：🔴🔴🔴🔴🔴
纵向五连：
🔴
🔴
🔴
🔴
🔴

斜向五连：
🔴
 🔴
  🔴
   🔴
    🔴
```

#### ✅ B5: 特种棋子测试
**操作步骤**：
1. 先通过五连生成特种棋子
2. 点击特种棋子（亮黄色圆形）
3. 尝试移动特种棋子

**预期结果**：
- 特种棋子可以正常移动
- 特种棋子**不能**参与五连合成
- 特种棋子一直保留，不会被消除

#### ✅ B6: 步数系统测试
**观察位置**：屏幕左上角显示步数

**预期结果**：
- 显示"剩余步数: 30"（初始值）
- 每次移动，步数减1
- 如果触发合成，步数仍然减1（合成不额外消耗步数）

#### ✅ B7: 结束判定测试
**三种结束条件**：

1. **步数耗尽**
   - 移动30次后（或你设置的步数限制）
   - Console显示："游戏结束: OutOfSteps"

2. **手动结束**
   - 按下空格键
   - Console显示："游戏结束: Manual"

3. **棋盘填满**（较难触发）
   - 所有可操作格子都有棋子
   - Console显示："游戏结束: BoardFilled"

#### ✅ B8: 阶段结算测试
**操作步骤**：
1. 触发任意一种结束条件
2. 查看Console窗口输出

**预期结果**：
- 显示："游戏结束: [结束原因]"
- 显示："结算完成: 移除X个普通棋子, 保留Y个特种棋子"
- 所有普通棋子消失
- 所有特种棋子保留在原位置

### 第6步：重新测试

- 按下 **R键** 重新开始游戏
- 或 点击 **Stop按钮**（Play按钮变红时）停止测试

## 🎨 方式二：使用UI系统测试（适合完整功能展示）

这种方式需要手动搭建UI，但可以展示完整的游戏界面。

### 第1步：创建Canvas

1. **创建Canvas**
   - Hierarchy → 右键 → UI → Canvas
   - 选中Canvas，Inspector设置：
     - Render Mode: Screen Space - Overlay
     - Canvas Scaler → UI Scale Mode: Scale With Screen Size
     - Reference Resolution: 1920 × 1080

### 第2步：创建棋盘容器

1. **创建Panel**
   - Canvas → 右键 → UI → Panel
   - 命名为 "GridPanel"
   - Rect Transform 设置：
     - Anchors: 中央
     - Width: 600
     - Height: 600
     - Pos X: 200 (稍微靠右，为左侧显示区预留空间)
     - Pos Y: 0

2. **添加Grid Layout**
   - 选中 GridPanel
   - Add Component → Grid Layout Group
   - 设置：
     - Cell Size: X=60, Y=60
     - Spacing: X=0, Y=0
     - Constraint: Fixed Column Count = 10
     - Child Alignment: Middle Center

### 第3步：创建格子预制体

1. **创建按钮**
   - Hierarchy → 右键 → UI → Button - TextMeshPro
   - 命名为 "CellPrefab"
   - 删除按钮下的 "Text (TMP)" 子对象（不需要文字）

2. **设置按钮样式**
   - Rect Transform:
     - Width: 60
     - Height: 60
   - Image (Background):
     - Color: 灰色 (R:200, G:200, B:200)
   - Button:
     - Transition: Color Tint
     - Normal Color: 白色
     - Highlighted Color: 浅黄色
     - Pressed Color: 深黄色

3. **保存为Prefab**
   - 拖动 CellPrefab 到 Project 窗口（Assets文件夹）
   - 删除Hierarchy中的CellPrefab

### 第4步：创建步数显示

1. **创建文本**
   - Canvas → 右键 → UI → TextMeshPro - Text
   - 命名为 "StepsText"

2. **设置文本**
   - Rect Transform:
     - Anchors: 右上角
     - Pos X: -150
     - Pos Y: -50
     - Width: 250
     - Height: 80
   - TextMeshPro:
     - Text: "剩余步数: 30"
     - Font Size: 36
     - Alignment: 左对齐
     - Color: 白色

### 第5步：创建控制器

1. **创建空对象**
   - Hierarchy → 右键 → Create Empty
   - 命名为 "BoardUIController"

2. **添加脚本**
   - Add Component → BoardUIController

3. **配置参数**
   - Steps Text: 拖入 StepsText
   - Grid Root: 拖入 GridPanel 的 RectTransform
   - Cell Prefab: 拖入保存的 CellPrefab
   - Board Width: 10
   - Board Height: 10
   - Initial Piece Count: 15
   - Step Limit: 30

### 第6步：运行测试

1. 点击 Play 按钮
2. 进行与"方式一"相同的功能测试

## 🐛 常见问题排查

### 问题1：点击Play后没有显示棋盘

**原因可能**：
- 摄像机位置不对
- Canvas设置错误

**解决方法**：
1. 检查Scene窗口是否能看到棋盘
2. 确认Main Camera存在
3. 对于2D测试：Camera → Projection 改为 Orthographic

### 问题2：格子太小看不清

**解决方法**：
- 方式一：在BoardSimpleTest2D中，格子大小是固定的，可以调整Camera的Orthographic Size（越小看得越清楚）
- 方式二：调整GridPanel的Width/Height和Grid Layout的Cell Size

### 问题3：点击格子没有反应

**检查项**：
1. 确认点击的是空格子（有棋子的格子不能作为移动目标）
2. 确认已经先点击了一个棋子（格子变黄）
3. 确认目标格子与选中棋子相邻（上下左右，不能斜向）
4. 查看Console是否有错误信息

### 问题4：五连没有触发合成

**检查项**：
1. 确认是5个**相同颜色**的棋子
2. 确认这5个棋子**连成一线**（横/纵/斜）
3. 特种棋子（亮黄色圆形）不能参与合成
4. 查看Console是否有"合成成功"的日志

### 问题5：编译错误

**常见错误**：
```
CS0103: The name 'xxx' does not exist in the current context
```

**解决方法**：
1. 打开Console窗口（Window → General → Console）
2. 双击错误信息，会自动打开出错的文件
3. 截图错误信息，寻求帮助

### 问题6：Game窗口是黑屏

**原因**：缺少摄像机

**解决方法**：
1. Hierarchy → 右键 → Camera
2. 选中Main Camera
3. Transform → Position 改为 (5, 5, -10)
4. 对于2D游戏：Projection 改为 Orthographic

## 🎯 高级测试场景

### 场景1：测试五连边界情况

1. **超过5个连线**
   - 尝试形成6个或更多相同棋子的连线
   - 预期：只有最靠近移动终点的5个被合成

2. **多个方向同时满足五连**
   - 移动一个棋子，同时形成横向和纵向五连
   - 预期：优先处理其中一个方向

### 场景2：测试特种棋子保留

1. **生成多个特种棋子**
   - 触发多次五连，生成3-5个特种棋子
2. **触发游戏结束**
   - 观察结算时特种棋子是否都保留

### 场景3：测试障碍物阻挡

1. **尝试移动到障碍物**
   - 预期：无法移动，Console无错误
2. **尝试绕过障碍物**
   - 预期：可以正常移动到障碍物旁边的空格
